# 读者统计

后台“增长”页（`/admin/metrics`）回答三个问题：读者从哪来，读了什么，有没有留下来。数据由站点自己采集，不接第三方统计脚本。机器流量在写入前就过滤掉，过滤掉多少单独显示。

## 采集

浏览器每打开一页，向 `POST /api/site/analytics` 报一次浏览（`apps/web/app/lib/readership.ts`）：

- 页面路径；整页打开还是站内跳转；
- 整页打开时，从哪个站点进来（`document.referrer`，服务器只留域名），以及 `utm_source`、`utm_medium`、`utm_campaign`（没有 `utm_source` 时取 `ref`）和分发标记 `?via=`；
- 浏览器首选语言、是否触屏；
- 浏览器在本地存储里记下的**第一次访问日期**和**上一次访问日期**（台北日期）。

离开或切走页面时再报一次 `page_leave`，带这一页可见的毫秒数（单页最多计 30 分钟）。收藏、订阅、原文点击这些操作照旧报到 `POST /api/site/events`，同时挂到当前会话上。打开过后台的浏览器在操作里同样带上站长标记，不计入。

工坊（`modules/scenes`）报两个操作，目标是工坊页面的英文路径（例如 `/chronicle/iron`，中文页面也报这个，语言看会话）：`workshop_start` 是一局里读者第一次亲手操作（主按钮、操作按钮、场景里的操作点、阶段按钮；差分机是第一次转动），载入和每次复位或“再玩一次”后各算一局，自动演示自己推进的不算；`workshop_finish` 是这一局走到最后，前提是读者在这一局亲手操作过，挑战类由自动演示代为完成的局不算，差分机算到 10² 算完成。服务器只接受站内存在、不带参数的页面路径。进了工坊却没有操作的人数，用这个页面的浏览减开始数来看。

加速史首页在时间轴上移动不算新页面，所以另报两个操作，目标都是空的：`chronicle_move` 是这次打开后第一次离开开始的那张图，`chronicle_deep` 是停在第 6 张不同的图上（拖动时路过的不算）。每次打开各报一次，2026-11-06 起有数。

服务器把浏览写进两张表（`packages/backend/src/site/sessions.ts`）：

| 表 | 一行是 | 内容 |
|---|---|---|
| `site_sessions` | 一次访问 | 访客摘要、开始和最后活动时间、浏览数、可见时长、落地路由和具体落地页、退出路由、渠道、来源域名、utm、浏览器、系统、设备、国家/地区、语言、首次和上次访问日期 |
| `site_hits` | 访问里的一步 | 浏览（路由和具体路径、可见时长）或操作（事件名和目标），按顺序编号 |

按天的 `site_pageviews_daily` 和 `site_events_daily` 照旧累计，周报和 `deploy/update.sh --stats` 读它们，2026-10-10 以来的历史都在里面。

### 一位访客

同一天里，同一网络地址加同一 User-Agent 算一位访客：`sha256(当天的盐, 地址, UA)` 取前 32 位十六进制。盐存在 `site_salts`，每天一条随机值；新的一天第一次用到时删掉之前所有的盐，之后旧摘要无法重算，不同日子的访问也连不起来。不用 Cookie，不存地址。

所以“独立访客”跨天去重靠浏览器自己记的上次访问日期：一个浏览器在所选时段里只在它第一天被计数（那天的上次访问早于时段开始）。清过浏览器数据、无痕窗口、禁用本地存储的读者每天都算新访客，访客数偏高、新访客占比偏高、留存偏低。同一网络后面同一型号手机的同一浏览器会合成一位，当天访客数偏低。

### 一次访问

同一访客两次活动隔了 30 分钟以上，算新的一次访问。整页打开时如果来源（来源站或 utm）和正在进行的访问不同，也算新的一次：从 X 点回来和刚才从 Google 来不是同一次。站内跳转从不改变访问的来源。跨过台北零点会开始新的访问（访客摘要换了）。

### 渠道

依次判断，先命中的为准：

1. `?via=newsletter` 或 `utm_medium` 是 email/newsletter → 邮件
2. `utm_medium` 是 cpc、paid、display 等 → 付费
3. 来源站是 AI 助手（chatgpt.com、perplexity.ai、claude.ai、gemini.google.com……）→ AI 助手；是网页邮箱 → 邮件；是搜索引擎 → 搜索；是社交站 → 社交；其他来源站 → 外链
4. 没有来源站时看 `utm_source`（ChatGPT 常常只加 `utm_source=chatgpt.com`）
5. `?via=share` → 分享链接
6. 其余 → 直接访问

名单在 `sessions.ts` 里，看到“外链”里出现明显该归类的站点就补进去。

## 过滤机器

按顺序，命中一条就不写入会话，只在 `site_events_daily` 里按原因记一次 `view_filtered`：

| 原因 | 判断 |
|---|---|
| `owner` | 这个浏览器打开过后台（后台布局在本地存储里做了标记） |
| `automation` | `navigator.webdriver` 为真 |
| `agent` | UA 为空，或带 bot、crawl、spider、headless 等字样 |
| `reloads` | 同一 UA 当天整页打开超过 15 次而几乎不站内跳转（`readerFilter`，规则同 traffic-metrics 技能） |

还有一类要等会话结束才看得出来：电脑上的直接访问（没有来源站和 utm），只开了一页、页面可见时间不到 1 秒、也没有任何操作（订阅框出现、分发访问这类页面自己发的事件不算操作），而且距最后一次活动已超过会话间隔（30 分钟）。会执行页面脚本、却从不把页面显示出来的抓取程序就是这样，换着地址抓，前四条都拦不住。这类会话照常写入，但看板统计时不算，按 `unseen` 单列在过滤掉的流量里；规则在 `admin/growth.ts` 的 `unseen()`。还开着的页面要等它报完可见时间才判断，所以刚打开的会话会先算进去。手机关掉页面时常常来不及报可见时间，搜索或外链带来的会话也是真人居多，这两类都照常计入。

不跑 JavaScript 的爬虫不会发信标，本来就不进统计。换着真实 UA 轮流抓、又跑 JavaScript、还会站内跳转的爬虫仍可能混进来；如果访客数突然翻倍而 Search Console 点击没动，先按技能里的方法查服务器日志。

## 看板

时段（今天、昨天、7/28/90 天或自定义）和对比的上一段同样长的时段放在页首。任何表格里的值都可以点，整页就限定到这个值；筛选可以叠加（例如“搜索 × 手机 × 看过 /subscribe”）。转化目标可选任一操作，默认是“订阅被接受”。

| 标签页 | 内容 |
|---|---|
| 概览 | 独立访客、会话、浏览、跳出率、互动会话率（≥2 页、≥10 秒或达成目标）、平均互动时长、新访客占比、转化率，各带环比；按天（单日按小时）趋势叠上一时段；此刻在读；过滤掉的机器流量 |
| 获客 | 渠道、来源站、具体落地页、utm 三项、新/老访客、国家、语言、浏览器、系统；每行带访客、会话、跳出、互动时长和转化率 |
| 内容 | 按路由和按具体页面的浏览、会话、入口、退出率、平均可见时长；退出路由；会话里的操作；最常见的阅读路径 |
| 转化 | 自己搭的会话漏斗（任意页面、某个路由、某个操作，最多 8 步，按顺序在同一会话里达成）；订阅漏斗按入口和语言；净收藏；各工坊的开始、完成与完成率 |
| 留存 | 按首访周分组的周留存矩阵 |
| 周报 | 每周的浏览、订阅、Search Console 展示/点击/收录、页面×查询词 |
| 出口 | 按天累计的操作次数和 MCP 调用 |

接口都在 `/api/admin/growth*`（`packages/backend/src/admin/growth.ts`），参数与页面地址相同。
