# P1：搜索明细、日报阅读入口与分发归因

## 本次实现

- Search Console 周任务增加 page × query 快照（点击、展示、CTR、平均排名），后台按展示排序显示前 100 条，比较紧邻前一周同 property、同 URL、同查询。数据库保留最多 25,000 条 API 返回的主要查询；达到上限会提示，未采集的旧周为 null。接口只返回候选和前周匹配项，避免将全部历史明细传给浏览器。
- 日报增加“今天发生了什么 / 持续跟进”：复用公开读取层返回的可用报道，去重并保留编辑顺序；只有已记录 followUp 的条目才列为跟进，并链接此前日报。不从摘要自动推断影响或预测，不新增模型调用。
- 日报邮件内的网站链接带 `via=newsletter`；分享/复制带 `via=share`。外部原文、确认和退订链接不加标记。canonical 沿用不含查询参数的规则。
- 当前标签页在内存中延续最近一个有效来源，刷新后只有链接仍带标记才恢复。站内访问按页面次数计数；页面累计可见 15 秒计一次阅读，隐藏时间排除，离开页面清理计时。不是 UV，不是读完率，也不能证明真人阅读。
- 首次登记时仅保存白名单来源，重复登记及重订阅不改写；确认数按首次 confirmed_at 归周。历史订阅者保持未知，不补写归因。计数为自报数据，不作为结算依据。

## 数据与上线

0136 / 0137 各新增一个可空列，没有删数据或回填。已有搜索快照、订阅和公开出口保持原有读取规则。仍由现有安全阀和周任务控制，开发验证不调用线上模型、不发邮件、不部署。Search Console 日期为太平洋时间，站内计数为 Asia/Taipei，周对比不能当成同一时区的逐日漏斗。

Google 的查询 API 不保证返回所有行，查询隐私过滤和截断使明细之和可能低于总数：[官方说明](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)。排名变化为本周减前周，负数表示平均位置向前。

## 运营后续

采集到真实明细后，按页面检查查询意图、标题和导语，只改事实支持的措辞，保留稳定 URL、原文证据和更新日期。现有历史聚合数据不能反推出具体查询，不批量改写标题。

渠道目前只区分日报邮件与读者分享。选定具体外部分发渠道、撰写“变化 / 影响 / 后续关注”的人工核实材料并实际发布，属于后续运营；本次没有代发。影响与未来关注需要独立证据，现有 report contract 没有这类字段，本次不虚构。
