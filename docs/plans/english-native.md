## 目标与边界

把英文从“中文编辑结果的译文”改为新闻产品的主语言：原始报道直接产出英文编辑稿，事件与报告直接用英文写作，网站、邮件和公开出口默认英文。中文继续作为可选择的辅助 edition。

本计划不修改站名，不擅自调整生产信源、分类、重要性标准或评分门槛，不重写法律条款。模型调用仍限于 worker，经过回执和预算熔断；全文许可、匿名公开内容、统一 publication 读取层保持现有规则。

生产配置、付费历史处理与部署属于后续执行事项，本计划本身不执行这些动作。

## 推荐产品决策

| 项目 | 推荐方案 | 说明 |
|---|---|---|
| 主编辑语言 | en | 任何来源直接生成英文编辑稿，不经中文中转 |
| 辅助语言 | zh | 中文 edition 异步生成，不阻塞英文发布 |
| 网站默认 | en | 所有未手动选择语言的读者与爬虫均得到英文；保留中文入口 |
| 语言 URL | 英文使用现有路径；中文使用 /zh 前缀 | 保留已有英文链接权重，建立可访问、可缓存的语言版本 |
| 日报业务时区 | America/New_York | 明确以美东日期定义期号、取稿窗口、归档与发布 |
| 日报发布时间 | 美东每日 08:00 | 自动处理夏令时；西海岸对应 05:00，需要运营确认是否符合受众 |
| 阅读时间显示 | 默认标明美东时间，可选读者本地时间 | 语言、业务时区和显示时区独立，不把英文等同于某个时区 |
| 对外分发 | 英文默认，明确提供中文版本 | RSS、v1、MCP、Markdown、分享图和邮件一起覆盖 |

以上是实施基线建议；日程、邮件订阅迁移方式及信源取舍需在对应阶段落实为明确产品决定。旧报告期号和统计边界保留，避免历史记录被重新解释。

## 目标链路

原文采集与语言标记 → 原文存储 → 内容理解与评分 → 英文编辑稿 → 英文 publication → 英文事件归组/综述与报告 → 网站、邮件及公开出口。

英文发布后，worker 按需生成中文 edition。中文缺失时可显示英文原文并明确状态，不触发实时模型调用。原生英文稿不依赖翻译队列；中文编辑完成度不影响英文公开可读性。

## 阶段 0：生产盘点与基线

工作：

- 对生产数据库只读盘点来源、原文语言标记、最近新闻量、有效英文 edition、缺失/失效 edition、全文许可和报告状态。
- 记录翻译队列积压与完成延迟、编辑模型耗时、按用途的模型请求数量；不把现有请求数量预算称为美元费用上限。
- 盘点全部公开路由、SSR/client fetch、SEO、RSS/v1/MCP/Markdown/OG、邮件及静态内容。
- 从实际来源中挑选英文、中文和其他语言样本，以及 X 短帖、长文、引用、编辑覆盖、撤回、事件更新、日报重发等边界样本。
- 信源盘点结果单独列出，由运营者决定增删；不因美国流量目标直接替换来源或调低门槛。

交付：覆盖矩阵、代表样本、线上语言与性能基线、历史待处理数量。

验收：能够区分原文语言、主编辑语言、edition 语言、正文语言和 UI 语言，能解释每个出口当前返回的语言。

## 阶段 1：引入明确的编辑语言与兼容存储

涉及：database/migrations、editorial/analyze.ts、publication/publish.ts、publication/content-source.ts、publication/content-language.ts、contracts。

工作：

- 通过增量迁移为分析、发布、事件及报告添加明确的主编辑语言信息；旧记录标记为现有语言，不能只改标签冒充英文。
- 新分析结果使用语言中立的 title/summary/reason 字段；旧 title_zh/summary_zh/reason_zh 保留兼容读取，避免把英文写进中文字段。
- editions 支持 en 与 zh，保存源语言、源文本 fingerprint、目标语言、模型和来源；主稿和辅助译文有明确关系。
- 指纹包含主编辑语言及当前公开文本/报告 revision 等内容身份；切换主稿后，旧译文不能误判为有效。
- 对外 DTO 明确 editorialLanguage、contentLanguage 和 bodyContentLanguage；兼容既有客户端，不在此阶段默认切换 v1。
- 语言覆盖只发生在统一 publication 层，继续先执行许可、撤回和可见性投影。

验收：旧中文主稿+英文 edition、新英文主稿+中文 edition 可以共存；编辑变更使相应 edition 失效；错误语言和不完整字段不能作为已就绪版本输出。

回滚：旧列和旧读取路径保留；新写入能力可关闭。切换英文主稿之后不能直接回滚到无法识别英文主稿的旧程序，须保留兼容版本作为回滚目标。

## 阶段 2：直接用原文生产英文编辑稿

涉及：industry/prompts、editorial/writing.ts、analyze.ts、events、reports、模型回执版本。

工作：

- 内容理解直接读取原始材料，输出自然英文标题、摘要和推荐理由。提示词可以使用英文，但判断依据和评分结构不随提示词语言改变。
- 改造目前依赖中文长度、中文密度、短推翻译和 titleZh 等字段的确定性处理；英文长度按词数/字符及产品版面制定，保留事实和主体校验。
- 原标题自洽时允许保留或轻编辑；英文稿从原文生成，不能把现有中文输出翻译后称为 native。
- 专有名词、数字、单位、归因、链接和引用保留；使用美式英文编辑风格，USD 等单位明确，避免中式直译。
- 事件标题、摘要、综述、最新进展、时间线与报告直接以英文编辑稿为输入并输出英文；仍允许跨语言报道归入同一事件。
- 增加中文辅助 edition 队列，优先用户可读内容。英文原稿更新后按同一指纹规则补译中文。
- 保留原文正文；明确标记为英文的许可全文直接展示原文。非英文许可正文可直接从原文生成英文正文，避免使用中文全文作为中转。
- 正文与标题摘要独立状态；无法确认语言的内容先验证或标记 unknown，不凭来源域名宣称英文。
- 同一源版本和 prompt version 的请求仍用回执复用；重试不重复付费。新版本提示词必须使旧模型答案失效。

验收：新新闻、事件、报告不依赖 English localization 队列即可发布英文；中英文与其他语言来源样本事实一致；正文/引用/媒体与全文许可边界保持正确。

## 阶段 3：历史与实时内容平滑过渡

工作：

- 首先只对新稿启用英文主编辑；历史稿保留中文主稿和已有英文 edition，统一读取层同时支持两类记录。
- 活跃旧事件允许在下一次真实更新时转为英文主编辑；存储语言与文本必须同时更新，旧中文可保存为匹配新源的辅助 edition 或重新生成。
- 历史报告保留原期号、内容与 revision；现有有效英文版继续服务英文页面，不为语言迁移重发旧邮件。
- 如需把历史主稿真正转换为英文，另做有数量、预计请求、预算和批次回滚记录的任务；不作为首发前置条件。
- 批量作业默认只读导出和 dry-run；写入前按当前文本指纹再次验证，防止覆盖编辑更新。

验收：热门旧稿仍能英文展示，新稿直接英文；失效译文状态透明；无重复新闻、事件、报告或邮件；历史 URL 与日期保持可追溯。

## 阶段 4：稳定英文 URL、中文入口与 SEO/缓存

涉及：web 路由、locale/content-fetch/seo、server、入口仓库 edge/src/route.mjs。

工作：

- 现有无语言前缀路径固定为英文，例如 /all、/items/:id、/what-is-eacc；中文镜像入口为 /zh/...。
- URL 决定内容和 UI 语言；cookie 仅保存选择偏好和辅助切换，不让相同英文 URL 随 Accept-Language/cookie 变成中文。
- 语言切换跳到对应地址，保留适用的筛选参数；不自动按 IP 跳转。中文偏好用户的入口/旧链接行为须明确，避免语言 cookie 导致可缓存 URL 内容变化。
- 对具备对应版本的页面生成自引用 canonical、双向 hreflang=en/zh-CN 和英文 x-default；没有实际中文版本的固定英文页不虚构 alternate。
- html lang、metadata、OG 与结构化数据准确描述各字段实际语言；正文回退时不能把整篇中文声明为英文。
- 网站请求显式传 lang；SSR、导航 .data、分页、展开、搜索和详情全部覆盖两个路径版本。
- 为固定语言、匿名、无个性化输出的公开页面恢复合理共享缓存；检查 onboarding、cookie 读取、Set-Cookie、管理员请求、错误和重定向。后台及真正个性化内容继续 no-store。
- 新增 /zh 路由同时更新并发布入口 Worker；覆盖 .data 分流，避免重现 HTML 正常而菜单跳转 404。
- 全部英文 UI、空状态、通知与静态配置文案盘点；分类/标签的稳定 ID 不变。法律页英文文本由运营者确认后发布。

验收：同一英文 URL 在 en/zh 请求头和不同语言 cookie 下均输出英文；中文 URL稳定输出中文；菜单导航和直接打开一致；缓存无语言或权限串用；SEO alternates 均能访问。

## 阶段 5：全部公开出口与英文邮件

工作：

- RSS 提供明确的英文默认地址及中文地址，feed language、标题、摘要和链接一致。
- v1 API 的默认语言属于兼容性变更：先提供显式 lang=en|zh 和实际返回状态，再决定通过新版本或有公告的迁移切换默认；不能突然让旧客户端默认响应换语言。
- MCP、Markdown、llms.txt 的语言说明和访问方式明确；分享图使用当前目标语言的已存稿件，不触发模型调用。
- 邮件订阅保存 language；新订阅默认英文，确认邮件、日报、退订和偏好页一致。
- 既有订阅者语言未知，不能由历史中文模板推断本人偏好。迁移前确定保留中文或提供偏好更新机制；此计划不代发通知。
- 英文邮件从英文 publication/report 投影生成；辅助语言未就绪时的等待、跳过或标记策略明确，禁止悄悄发送混合语言邮件。
- 邮件幂等键包含期号与发送语言/批次身份，防止每种语言重复发送；不重发历史报告。

验收：英文订阅完整闭环为英文；原稿、报告和邮件实际语言一致；错误重试、未知发送状态及退订保持既有保障；旧 API/feed 客户端有明确兼容路径。

## 阶段 6：美国时间策略

工作：

- 分开定义 reportTimeZone、reportPublishTime、displayTimeZone；使用 IANA 时区及其夏令时规则，不使用固定 UTC-5 代替美东。
- 新报告采用美东日界线和取稿窗口；期号携带可追溯的业务时区信息，明确切换日，防止旧北京时间期号与新期号冲突或重复选稿。
- 归档、today/yesterday、搜索日期、热点历史切片、订阅调度和报告 catch-up 逐一核对；报告日界线和新闻历史筛选日界线分别定义，不能全局替换 beijingDate。
- 默认绝对时间清楚注明美东，若提供“本地时间”显示则标明时区，并避免 SSR/hydration 差异。
- 日报以美东 08:00 为提案；周报/月报的日期与时间单独确定。邮件等待对应报告就绪再发送。
- 测试夏令时起止、美国与中国跨日、新旧归档边界、调度遗漏补跑及幂等发送。

验收：美国读者能理解日报对应哪一天、何时发布；切换无重复期号、漏稿、重复邮件；历史记录仍按原定义可解释。

## 上线顺序与发布门槛

1. 只读盘点与产品决策落实。
2. 发布兼容数据结构和读取层，公开默认行为保持现状。
3. 小范围启用英文主编辑，验证新稿、事件、报告及中文辅助版；通过配置恢复旧写入路径。
4. 全量启用英文主编辑，观察队列延迟、质量、调用量和错误。
5. 发布固定语言 URL、Worker 分流、SEO 和缓存；验证 .data 与整页请求。
6. 发布英文邮件和明确语言的公开出口，兼容性变更按独立发布处理。
7. 在明确日期切换新报告时区/调度，避免同时修改语言与期号边界导致难以排错。
8. 根据实际需求处理历史数据。

开发与测试保持采集、模型、推送及 IndexNow 安全阀关闭，不访问外部服务。重要行为以真实数据库/本地 HTTP stub 测试；执行 typecheck、空测试库迁移与 backend tests、web build 与 web tests，以及运行站点后的 smoke。浏览器验收涵盖英文首屏、中文切换、菜单、搜索、正文、报告和订阅。

生产发布使用 deploy/update.sh；入口 Worker 使用其仓库的发布流程。每阶段记录版本、开关、数据批次、验证结果和兼容回滚版本。不得把存在新英文主稿的数据回滚给仅理解旧中文字段的应用。

## 成功标准与监控

- 新稿英文标题/摘要/推荐理由直接生成，不消耗英文化二次翻译请求。
- 新事件与报告主内容为英文，正文状态独立准确。
- 英文入口不因浏览器语言发生中文首屏或中文 metadata。
- 所有出口清楚定义默认语言和回退行为；英文邮件完整闭环可用。
- 美国日期与发布时间明确，夏令时和切换日正确。
- 持续记录英文主稿失败率、中文 edition 完成延迟、未知原文语言比例、按用途请求量、SSR/API 延迟、缓存命中及邮件结果；初始盘点后制定数值阈值，不凭空承诺实时翻译或美元预算。
