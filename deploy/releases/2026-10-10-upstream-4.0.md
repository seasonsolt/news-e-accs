# 合并上游 4.0.0（不删表）、英文版补全与新标志

这次发布带上游 AIHOT 4.0.0：引擎改为从 AIHOT 线上代码导出，站点文件搬进 `site/`，模型榜、Codex 重置监控和主题大事记移出框架。

**本站没有采用上游的删表迁移。** 上游 `0084`–`0106` 共 23 个迁移会删除模型榜（`lb_*`、`fx_rates`）、重置监控（`monitor_*`）、`topics`、`stored_files`、`regroup_pending` 等表，以及 `service_prices`、`translations`、`admin_users`、`sources` 上的几列。这些迁移从本仓库删除，生产库上从未执行：

- 模型榜会以站点模块（`site/modules`）的形式恢复，直接使用保留下来的表和历史数据。
- 删表不是向后兼容的增量，执行后 `deploy/update.sh --rollback` 回到 `dfa187f` 时旧代码会查询不存在的表；保留下来，回滚仍然可用。旧代码写入 `topics` 时需要的 `grp` 等列也都还在。
- 新代码不读写这些表和列；`tests/architecture.test.ts` 的 `RETAINED` 列出了它们。模型榜模块恢复后，从名单里移除它用到的表。
- **以后同步上游时，继续排除这些删表迁移**，不要把它们重新合并进来。

本次新增的迁移（`0044`–`0057`、`0083`）只加列、加索引、加表，以及放宽 `admin_sessions.auth_method` 的约束（旧约束允许的值都在新约束里），回滚旧版本时可以保留。

模型榜在模块恢复之前下线：`/leaderboard` 返回 404，首页不再链接它；数据库里的数据不受影响。Codex 重置监控在本站本来就关闭。没有新增顶层路由，入口 Worker 不用改。

后续已将模型榜恢复为 `modules/leaderboard/` 站点模块，由 `site/modules/` 的三份清单启用。页面、接口、评测采集和四次每日计算继续直接使用保留的 `lb_*`、`fx_rates` 表和历史记录，没有新增迁移或删表；模块恢复后，八个实际使用的表均从 `RETAINED` 移除；只保留旧版同样不读的五个早期列（`lb_models.input_price_usd`、`output_price_usd`、`metadata_updated_at`，`lb_rankings.uncertainty`、`component_scores`），继续供旧版本回滚使用。

同一次发布还包括：

- 英文版的分类横幅改用给读者看的说明（taxonomy 的 `note`），不再显示给模型看的归类说明；`/chronicle` 的时代、里程碑、指标有了英文（`industry/chronicle/en.json`，接口按 `lang` 返回），时间刻度和距今时长也翻译成英文。
- 中文优先的浏览器第一次打开英文页面时，提示有中文版（不自动跳转）。
- 事件视界标志替换齿轮，成为站点标志和图标（`site/brand/`，位图由 `scripts/brand-icons.ts` 生成）。
- 修复 origin/main 上失败的网页测试（概念页的 alternate 链接改为按 `SITE_URL` 判断）。

本地已用隔离数据库从零迁移，通过类型检查、网页构建、网页测试和后端测试。后端只有 `outbound secure-proxy` 一项失败，在没有本次改动的 main 上本机同样失败（本机 node 是 v26，CI 用 Node 24），以 CI 结果为准。部署须等 GitHub Check 通过，再由 `deploy/update.sh` 做版本健康检查和生产 smoke。
